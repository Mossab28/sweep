# sweep v2 — whole-PC audit → report → guided tidying

**Date:** 2026-06-19
**Status:** Design approved, building
**Author:** Mossab (Mossab28)
**Supersedes flow of:** `2026-06-19-sweep-design.md` (engine and safety model carry over)

## 1. Purpose

Running `sweep` with no arguments should **audit the whole computer**, present a
**report** of where space and clutter live (ranked worst-first), and then let the
user tidy zones one at a time — or all at once. The user should not have to know
or type which folder to clean; sweep finds the problem areas for them.

This also fixes the v1 performance problem: v1 asked Claude for one operation per
file, so a 760-file folder produced a ~760-operation response that appeared to
hang. v2 keeps every Claude response small (a short report; a compact tidy
**strategy**) and expands strategies into concrete operations **locally**, so it
scales to any folder size.

## 2. User flow

1. `sweep` (no path) → **audit scan** (local, read-only).
2. **Report** (generated by Claude, short output): a diagnosis plus a list of
   tidyable **zones ranked by priority** (heaviest / messiest first), each with a
   one-line reason ("1.6 GB, 760 files, lots of duplicates").
3. **Interactive menu:**
   - type a zone **number** → tidy that zone (strategy → plan → confirm → execute
     → undo) → return to the menu;
   - **`A`** → tidy **all** zones in sequence (one confirmation per zone);
   - **`Q`** → quit.
4. `sweep <path>` (with a path) keeps the v1 direct-tidy behaviour, including
   `-i "instruction"` for free-form custom requests and `-c/--claude-code`.
5. `sweep undo` unchanged.

## 3. Report-wide, action-safe split

- **Report (read-only)** may look broadly: per-zone stats for the user's content
  areas, plus a coarse "where the gigabytes are" overview of a few large readable
  consumers (e.g. `~/Library` aggregate, `/Applications` aggregate). Anything
  unreadable (SIP/TCC-protected, other users) is skipped silently — never an
  error, never a crash.
- **Tidying (moves files)** is **bounded to user content zones** only. The menu
  only ever offers safe, tidyable zones. The v1 safety guarantees all hold:
  refuse `/` and bare `~`, no real deletion (quarantine to `~/.sweep/trash/`),
  dry-run + confirm, full undo, skip system/noise dirs.

### Zones

Default tidyable zones (each scanned only if it exists): `~/Desktop`,
`~/Downloads`, `~/Documents`, `~/Pictures`, `~/Movies`, `~/Music`, and loose
files at the top level of `~`. System/noise is always excluded (`Library`,
`.config`, dotfiles, `node_modules`, `.git`, app bundles).

## 4. The scaling fix: strategy → local expansion

Instead of asking Claude for an explicit operation per file, sweep asks Claude for
a compact **Strategy** and expands it into concrete operations locally.

- `Strategy` (Claude output, small and bounded — independent of file count):
  - `summary: string`
  - `folders: Array<{ name: string; accepts: Category[] }>` — the target taxonomy
    (e.g. `{ name: "Images", accepts: ["image"] }`).
  - `quarantineDuplicates: boolean`
  - `quarantineJunk: boolean` — old installers, temp files, `.DS_Store`-style
    cruft.
  - `renameMessy: boolean` — normalise messy filenames.
- `Category` = `"image" | "video" | "audio" | "document" | "archive" |
  "installer" | "code" | "data" | "other"`.
- **Local expander** (`expandStrategy`) turns a zone's file `Index` + `Strategy`
  into a `Plan` (the existing `Operation[]` shape):
  - categorise each file by extension → `Category`;
  - route each file to the folder whose `accepts` includes its category →
    `move` (rename if messy and `renameMessy`);
  - if `quarantineDuplicates`: keep one of each duplicate group, `quarantine` the
    rest;
  - if `quarantineJunk`: `quarantine` files matching junk heuristics;
  - all destinations validated to stay inside the zone (reuse
    `assertPlanWithinBounds`).

Free-form custom requests (`sweep <path> -i "sort photos by year"`) keep the v1
per-file planner — that path is unchanged and not part of the menu flow.

## 5. Architecture

Builds on v1; new modules are isolated and individually testable. The Claude call
is the injected `PlanClient` everywhere, mocked in tests.

```
audit/      auditScan(zones, overviewRoots) → Audit. Light read-only walk
            (no hashing); per-zone ZoneStat + coarse overview consumers.
            Skips unreadable paths silently.
report/     buildReportPrompt(Audit) + createReport(audit, client) → Report
            (Claude; short JSON: summary + ranked zones).
strategy/   buildStrategyPrompt(ZoneStat-ish) + createStrategy(..., client)
            → Strategy (Claude; compact JSON). expandStrategy(index, strategy,
            target, quarantine) → Plan (local, no Claude).
categorize/ extToCategory(ext) → Category; junk + messy-name heuristics.
render/      + renderReport(Report) and renderMenu(zones) (framed pink UI).
cli/         default action (no path) = audit → report → menu loop; keeps
            `sweep <path>` (v1 direct tidy) and `sweep undo`.
```

**Reused unchanged:** `scanner.scan` (to get a zone's file `Index` at tidy
time), `executor`/`undo`, `store`, `render` box/rule/spinner, `safety`,
`schema.assertPlanWithinBounds`, `planner` (for the `-i` custom path).

### Key data types (added to `types.ts`)

- `ZoneStat { path; name; totalFiles; totalBytes; byType; approxDuplicateBytes;
  biggestFiles: {path;bytes}[]; looseFileCount }`
- `Audit { home; zones: ZoneStat[]; overview: {label;bytes}[]; scannedBytes }`
- `Category` (the union above)
- `Strategy` (the shape in §4)
- `Report { summary: string; zones: ReportZone[] }`
- `ReportZone { path; title; reason; priority: number; reclaimableHint?: string }`

## 6. Performance & the "infinite hang"

- Audit walk is local and light (stat only, no content hashing); excluded dirs
  are pruned before descent; unreadable dirs are skipped.
- Claude is only ever asked for the **report** and a per-zone **strategy** — both
  small, bounded outputs. The 300s `claude -p` timeout and the spinner stay.
- Concrete operations are generated locally, so a 760-file zone is instant to
  plan. This removes the v1 hang.

## 7. Testing (TDD)

- `categorize`: extension→category mapping; junk and messy-name heuristics.
- `audit`: per-zone aggregation correct; exclusions pruned; unreadable path
  skipped (no throw); biggest-files and approx-duplicate stats.
- `strategy.expandStrategy`: a strategy + a fixture `Index` expands to the right
  `move`/`quarantine`/`mkdir` operations; duplicates keep exactly one; every
  destination stays inside the zone.
- `report.createReport` / `strategy.createStrategy`: valid JSON parsed; malformed
  rejected with a friendly error; Claude mocked; markdown fences stripped.
- `render.renderReport` / `renderMenu`: ranked order, reasons, counts present.
- Menu selection: numeric pick, `A`, `Q`, and invalid input handled.

All filesystem tests use temp fixtures; no network in tests.

## 8. Out of scope (v2)

- Acting on system/app files (report shows them read-only; never tidied).
- Scheduling / background watching.
- GUI.
- Per-zone free-form custom instructions inside the menu (use `sweep <path> -i`).
